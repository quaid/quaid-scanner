# quaid-scanner v0.1.5

**Released:** 2026-08-02

## What's New

### Agent-Session Provenance

quaid-scanner is built to be driven by an agent, and v0.1.5 lets the agent sign its work.

A new `--provenance-file <path>` flag accepts a JSON record of the agent session that produced a
scan — the model(s) used, token counts, a session ID, an agent ID, and a timestamp. The scanner
embeds it, unchanged, in the report:

- **JSON output** gains a top-level `provenance` object.
- **Markdown output** gains a `## Report Provenance` section rendered as a readable table.

It is entirely opt-in. When no provenance file is supplied, no `provenance` key appears in the JSON
and no section appears in the markdown — existing output is byte-for-byte unchanged.

```bash
echo '{"models":["claude-opus-4-8"],"inputTokens":12450,"outputTokens":3210,"totalTokens":15660,"sessionId":"sess_abc123","agentId":"karsten-ospo","generatedAt":"2026-08-02T14:23:00-07:00"}' > /tmp/prov.json

quaid-scanner . --format json --quiet --provenance-file /tmp/prov.json
```

If the file is missing, malformed, or doesn't conform to the `ProvenanceInfo` shape, the scanner
emits a warning and continues without provenance — a bad provenance file never aborts a scan. The
`ProvenanceInfo` type is exported for library consumers who want to construct it programmatically.

This is the foundation for the agent-first scan → report → backlog workflow: a report can now carry
a machine-readable record of exactly which model generated it and at what cost.

### quaid-scanner Took Its Own Medicine

A health scanner that scores poorly on its own criteria is hard to trust. Between v0.1.4 and v0.1.5,
quaid-scanner's own self-scan went from **4.8/10 (HIGH risk) to 8.1/10 (LOW risk)** — not by
changing the scoring, but by closing real gaps the scanner had been flagging:

- A **`GOVERNANCE.md`** documenting the maintainer-led model, how decisions are made in the open,
  and the path to adding maintainers.
- A **`FUNDING.yml`** Sponsor link (Open Collective).
- A **CI workflow** that runs lint, build, and the full test suite with coverage on every pull
  request — so the 80%+ coverage gate is enforced, not just aspirational.
- **GitHub Actions pinned to commit SHAs** instead of moving tags, closing a supply-chain gap
  ([#123](https://github.com/quaid/quaid-scanner/issues/123)).

## Bug Fixes

- **Response-time and response-classification scanners no longer error against GitHub's GraphQL
  API** — Both ordered an inner `comments` connection by `CREATED_AT`, which `IssueCommentOrderField`
  no longer accepts; GitHub rejected the whole query and every finding degraded to a WARNING carrying
  the API error. The invalid ordering is removed, and GitHub's default comment order preserves
  first-response timing exactly. ([#213](https://github.com/quaid/quaid-scanner/issues/213))

## Under the Hood

- **Consolidated scanner directory exclusions** — Eight scanners each carried their own drifting
  `EXCLUDED_DIRS` lists; they now share one `excludeGlobs()` baseline, closing the drift that had
  reintroduced self-scan and cache bugs. The binary-artifacts scanner intentionally keeps
  `__pycache__` visible so it can still flag committed `.pyc` bytecode.
  ([#171](https://github.com/quaid/quaid-scanner/issues/171))
