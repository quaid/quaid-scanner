# quaid-scanner v0.1.4

**Released:** 2026-08-01

## What's New

### Signal Over Noise — Inclusive Language Scanner Quality

v0.1.4 is a quality release concentrated almost entirely on the inclusive language pillar.
Between v0.1.3 and v0.1.4, the inclusive scanners were surfacing enormous false-positive noise:
acronyms that were English words, technical terms inside code blocks, findings from the scanner's
own generated output, repeated findings for every file rather than grouped by pattern, and minified
bundles full of irrelevant matches.
The result was a pillar score of 0.0 for projects that had no real inclusive language problems.

This release eliminates that noise at the source.
The changes are extensive enough that projects scanning with v0.1.4 will see dramatically
different (and dramatically more accurate) inclusive language results than they did with v0.1.3.

**Acronym heuristic overhaul**

The assumed-knowledge scanner's acronym detector was generating the largest share of false
positives.
It flagged markdown emphasis words (`ALL_CAPS`), HTTP verbs (`GET`, `POST`, `PUT`), and common
English words (`IT`, `OR`, `AND`) as unexplained acronyms.
The fix came in four progressive PRs: skip emphasis and HTTP verbs, skip real English words via a
300-word dictionary, expand the dictionary and emphasis denylist, then replace the whole heuristic
with a principled suffix/length/vowel-pattern test.
The result is an acronym detector that flags actual unexplained acronyms.

**INI severity decoupled from INI tier**

INI tier 1/2/3 previously mapped directly to CRITICAL/WARNING/INFO severity.
This meant that a single tier-1 term in a README heading could drag the inclusive pillar to a
score that dominated the overall report.
INI tier is now a metadata classification label, independent of finding severity.
All inclusive scanner findings are capped at WARNING.
Tier 1 terms still get higher severity than tier 2 — but through scanner logic, not a hardcoded
mapping that ignores context.

**False-positive elimination across the board**

- Minified JavaScript bundles excluded from inclusive scanning
- Self-generated HTML and markdown report output excluded from re-scanning
- `.claude` and `.ainative` toolchain directories excluded from binary-artifacts scan
- Code fences excluded from prose pattern checks (assumed-knowledge scanner)
- Duplicate findings from multi-pattern file matches deduplicated
- `devDependency ^` prefix findings downgraded from WARNING to INFO

**Grouped markdown rendering**

`--format markdown` now collapses repeat findings (same category, multiple files) into a single
grouped block with a file list and representative context.
A project with 30 files containing the same diminishing-language pattern previously generated 30
separate finding blocks.
It now generates one block with the pattern, the suggestion, and the list of affected files.

### New Library Exports

**`renderHtml(report)`**

Generates a fully self-contained single-file HTML report with embedded CSS, pillar score bars,
severity-coloured findings, and collapsible sections.
No external dependencies — the entire report is one `.html` file.

```typescript
import { renderHtml } from 'quaid-scanner';
import { writeFileSync } from 'fs';

const html = renderHtml(report);
writeFileSync('scan-report.html', html);
```

**Per-term `referenceUrl` on diminishing patterns**

Each pattern in the diminishing-language scanner now carries its own reference link — Microsoft
Style Guide, Hemingway App, or the relevant authoritative source for that specific pattern —
instead of sharing a single generic link.

**INI tier in finding metadata**

Inclusive scanner findings now carry the INI tier (`1`, `2`, or `3`) as a metadata field,
independent of severity.
Consumers can filter by tier for reporting or triage without overloading the severity field.

**Per-term INI deep links**

`referenceUrl` on inclusive scanner findings now links directly to the specific INI term page
(`inclusivenaming.org/language-guide/terms/{term}`) instead of the INI homepage.
