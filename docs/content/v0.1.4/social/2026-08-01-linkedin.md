# LinkedIn Post: quaid-scanner v0.1.4

---

I shipped quaid-scanner v0.1.4 today.
This release exists because of a specific failure: I ran the scanner against real repositories and
watched it generate hundreds of inclusive language findings on projects that had done real
inclusive language work.
A scanner that cries wolf trains people to ignore the findings.
So I stopped adding features and fixed the scanner.

The root causes were several.
The acronym detector treated any uppercase letter sequence as an unexplained acronym — flagging
`GET`, `POST`, `IT`, `OR`, and markdown emphasis words as though they were insider jargon.
The scanner was reading its own generated reports and finding problems in its own output (a
finding about the word "master" in a Docker pinning scanner would trigger an inclusive language
finding about the word "master").
Minified JavaScript bundles were being scanned as project content.
A single INI tier-1 term in a project name was classified as CRITICAL severity, which drove the
inclusive pillar score to zero even when the rest of the project was clean.
And when one pattern appeared across thirty documentation files, it generated thirty separate
findings — making the real problems invisible in a wall of repetition.

Twenty-one bug fixes and four features later, here is what the output looks like for a project
with three instances of "simply" across its documentation and one legitimate acronym question:

```
[WARNING] Diminishing language: "simply" — 3 files
  docs/getting-started.md, docs/api-reference.md, docs/configuration.md
  Suggestion: Replace with more specific language. (Microsoft Style Guide)

[WARNING] Unexplained acronym: "API" in docs/getting-started.md
  Consider defining "API" on first use or linking to a glossary.
```

The real findings are there.
The noise is gone.
quaid-scanner's own self-scan inclusive pillar score went from 0.0 in v0.1.3 to 4.5 in v0.1.4.
The remaining warnings are legitimate.

For library consumers, v0.1.4 also adds `renderHtml()` — a new export that generates a fully
self-contained single-file HTML report with embedded CSS, pillar score bars, and severity-coloured
findings, no external dependencies needed.
The INI tier is now surfaced as a metadata label independent of severity, so consumers can filter
by tier for reporting without it affecting the score calculation.
Per-term INI deep links and per-pattern Microsoft Style Guide references make every finding
self-documenting.

The roadmap still has the Category B (ableist language) and Category D (cognitive load patterns)
scanners to write, and the cross-validation harness to build.
But the foundation has to be right before building up.
Accuracy is the prerequisite for usefulness.

`npm install -g quaid-scanner@0.1.4`

If you ran quaid-scanner before and discounted the inclusive language findings because there were
too many — this release is worth re-running.
The findings that remain are the ones worth acting on.
