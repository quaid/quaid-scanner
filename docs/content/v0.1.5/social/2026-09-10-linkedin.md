# LinkedIn Post: quaid-scanner v0.1.5

---

I shipped quaid-scanner v0.1.5 today, and it is about accountability in two directions: the reports
an agent produces, and the tool that produces them.

quaid-scanner is built to be driven by an AI agent — scan a portfolio of repositories, group the
findings, generate a backlog, open the issues. But until now there was a missing piece of
accountability. When an agent handed you a report and a backlog, nothing recorded which model
produced it or at what cost. v0.1.5 adds session provenance: a new `--provenance-file` flag accepts
a JSON record of the agent session — the models used, token counts, a session ID, a timestamp — and
embeds it directly in the report. JSON output gains a top-level `provenance` object; markdown output
gains a readable `## Report Provenance` section.

It is deliberately opt-in and fail-safe. With no provenance file, the output is unchanged from the
previous release. If the file is missing or malformed, the scanner emits a warning and continues —
a bad provenance file never aborts a scan. The point is to make an agent-run workflow auditable:
a report can now state, in machine-readable terms, exactly which model generated it and what it cost,
so a backlog you review a week later carries its own receipts.

The second half of this release is more uncomfortable, and more important. A health scanner that
scores badly on its own criteria is hard to trust, so this release ran quaid-scanner against
quaid-scanner and fixed what it found: a GOVERNANCE.md describing how decisions get made and how
someone becomes a maintainer, a funding link, a CI workflow enforcing linting and 80% test coverage
on every pull request, and GitHub Actions pinned to commit SHAs to close a supply-chain gap. Every
one of those was a finding the scanner had been reporting about itself.

And then the score went down.

A draft of these release notes claimed 8.1 out of 10, LOW risk. The published number is 6.5,
MEDIUM. Nothing regressed. This release also fixed the response-time scanners, which had been
erroring against GitHub's GraphQL API and quietly contributing nothing — and a pillar scores well
when nothing is measuring it. Now that they work, they report that the median first response on an
issue here is 1237 hours and that 83% of issues have no response at all. Both are true. Community
health reads 0.0.

That is the more useful version of dogfooding. It is easy to publish a number that went up. The
test of a health tool is whether you publish the one that went down because you made the tool more
honest. The same release also fixed four defects found by running the scanner against a real
external project, every one of which had been penalising the more sophisticated setup: SHA-pinned
GitHub Actions reported as unpinned, multi-stage Docker builds misread, Python virtualenvs scanned
in full, and — worst — a globally installed binary that did nothing at all and exited 0, which any
CI pipeline would have read as a clean pass.

If you evaluate open source health — for a dependency portfolio, an incubation candidate, or a grant
recipient — quaid-scanner v0.1.5 is worth a look, and it now shows its own scorecard openly.
